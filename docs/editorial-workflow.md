# Editorial workflow

## Public content model

Projects show working artifacts. Notes capture an argument, method, observation or
open question. Explorations are invitations to try an activity, not claims that
the owner has completed it. Existing algorithm notes remain in the dated archive.

The editorial voice is calm and concrete. Do not manufacture achievements, use
private experiences for an engaging story, or turn tentative questions into firm
personal opinions. Mark AI-assisted editorial work and distinguish hypotheses
from verified results. Cite original sources for factual research claims.

## A recurring review

1. Read the current default branch and open proposals before drafting; avoid repeats.
2. Review only the relevant recent context that is actually accessible. Retrieval is
   not guaranteed to contain every conversation. Record source gaps privately.
3. Select at most 1–2 substantial topics. A week without a useful topic needs no post.
4. Prepare the public wording in private. Remove identifying context rather than
   merely replacing names. Do not upload the source conversations or private notes.
5. For uncertain personal interpretation, present the candidate only to the owner
   in private conversation and wait for specific publication direction.
6. For material already suitable for public reading, a focused draft PR can be
   prepared after full contextual review. Everything in that PR is already public.
7. Build and check. Inspect generated pages, feeds, metadata, assets and the whole
   diff, including descriptions and commit messages.
8. Summarize the proposal privately. Do not merge, auto-merge or publish unattended.

## Scheduling boundaries

A schedule must be created in the assistant's automation service. Merely committing
this document or adding a cron-like label does not create a running task.

No website code reads chat history, holds account credentials or calls an AI API.
The browser only reads the static published content. The website itself cannot
receive an event after each private conversation. Use a scheduled editorial review
or explicitly ask the assistant to turn a particular conversation into public text.

Only the current run's available context and connected tools can be used. If access
fails, report the failure privately; do not fabricate an update or bypass access.

## Minimum bar for a public change

- Something new and useful, with no duplicated article or invented result.
- Clear distinction between facts, ideas, suggestions and personal views.
- No private identifiers or context; no third-party personal information.
- Evidence for completed work; citations for researched factual claims.
- Regenerated pages, stable old URLs, valid feed and working local links.
- Owner review for the initial relaunch and any uncertain attribution.

Pattern scanning is only an aid. A successful scan cannot establish that a narrative
is anonymous or appropriate to publish.
